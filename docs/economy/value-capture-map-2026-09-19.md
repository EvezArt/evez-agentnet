## 2. Portfolio consolidation rule

The 232-repository inventory is not 232 separate products.

The portfolio should be treated as a graph:

EVEZ-OS
  -> execution/runtime
  -> agent orchestration
  -> evidence/provenance
  -> deployment/operations
  -> mobile/edge
  -> creative computation
  -> games/simulation
  -> research

Repositories become implementation evidence and reusable modules. Products become customer outcomes.

## 3. What increases transferable value immediately

1. Reproducible demonstrations.
2. Passing tests attached to every commercial capability.
3. One-command installation for each sellable unit.
4. Public documentation that says exactly what works now.
5. Short demo videos or live endpoints backed by current timestamps.
6. Versioned evidence packets for deployments.
7. Customer-specific configuration separated from reusable core IP.
8. Clear licensing and dependency provenance.
9. Security review and secret-history cleanup.
10. Payment records attached to delivered artifacts once actual customers exist.

## 4. Evidence ladder

VERIFIED
Current test/deployment result reproduced from a known revision.

SUPPORTED
Multiple artifacts agree, but current execution has not been reproduced.

INFERRED
Reasonable conclusion from code or history.

PROPOSED
Commercial or architectural plan.

UNKNOWN
Insufficient evidence.

STALE
Previously supported but not recently rechecked.

CONTRADICTED
Conflicting evidence exists.

## 5. Economic ledger rule

Never collapse these states:

$0 observed
$X proposed
$X contracted
$X invoiced
$X received

The portfolio can have substantial replacement cost while having $0 verified cash revenue. That is not a contradiction. It is the difference between engineering labor/IP and realized market transactions.

## 6. Immediate value-capture sequence

OPPORTUNITY
-> VERIFY CURRENT CAPABILITY
-> PACKAGE ONE OUTCOME
-> SHOW REPRODUCIBLE DEMO
-> PRICE
-> HUMAN-APPROVED PROPOSAL
-> CONTRACT
-> DELIVER
-> VERIFY
-> INVOICE
-> RECORD PAYMENT
-> RETAIN

The economic engine must remain downstream of evidence. Otherwise it becomes a very sophisticated machine for producing invoices for software that may or may not exist, which is unfortunately a recurring human industry.
